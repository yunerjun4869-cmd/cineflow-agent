# 映序 CineFlow：先把一条商品故事讲顺

更新于 2026-11-09。

## 从什么事情开始

想给一只随行杯拍一条短视频：早晨出门、路上通勤、到办公室喝一口。三段画面单看都能用，但拼起来时，杯子变色了，主角换衣服了，故事也就断了。

映序想做的是帮创作者更早看到这些问题。先把脚本和设定确认下来，生成后抽帧检查，再把修改范围缩到具体片段。最终是否可用，还是由人来判断。

## 面向谁

| 使用者 | 具体任务 | 映序希望帮上的忙 |
| --- | --- | --- |
| 做 Shopify、Amazon 等海外商品内容的卖家 | 上新故事、商品使用场景、生活方式短片 | 把商品卖点转成镜头，并留意前后外观差异 |
| 做 TikTok、Reels、Shorts 的创作者 | 一条生活小故事、产品场景演绎、账号内容 | 逐步确认脚本，保持主角和场景的连续性 |
| 品牌与营销内容团队 | 为不同人群准备不同切入点的广告创意 | 按项目分别制作、检查，保留可用版本 |

这些是目标使用场景，还没有经过正式用户访谈或线上数据验证。平台名称仅说明内容去向，目前没有店铺接入、自动发布、广告投放或自动 A/B 实验。

面向海外市场也不等于已经做完国际化。界面目前是中文；当地表达、配音、字幕、商品描述和品牌细节需要人工检查。完整的多语言流程仍在计划中。

## 一次创作怎么走

| 步骤 | 人来做什么 | 系统做什么 |
| --- | --- | --- |
| 定方向 | 说清商品、受众、场景和卖点 | 生成脚本与分镜 |
| 定参照 | 确认角色、场景与参考图 | 供生成和审查使用 |
| 做片段 | 检查参数，启动视频生成 | 并行处理独立片段，限制服务商并发，有限重试 |
| 找问题 | 查看报告、判断是否真是问题 | 抽帧对照，给出片段位置和修改建议 |
| 改一段 | 选择问题片段，或换回历史版本 | 带着建议重生成，再次审查 |
| 看成片 | 人工确认可用性 | 进入后期合成流程 |

## 现在能做什么，接下来想做什么

| 范围 | 内容 |
| --- | --- |
| 创作流程 · 已实现 | 场景包、阶段编排、模型适配、并行生成、版本管理、单项重生成与后期流程 |
| 连贯创作 · 已实现 | 首／中／尾帧审查、报告面板、修复建议联动、单进程服务商限流、有限重试与测试 |
| 下一步 | 真实商品短片评测、问题帧对比、语言与字幕流程 |
| 更后面 | 跨集角色记忆、分布式任务恢复、内容平台连接 |

一致性审查和限流重试目前集中在“映序 · 连贯创作”场景，不自动覆盖所有模板。

## 接下来怎么判断它有没有用

先收集一批有人工标注的商品短片，用固定模型版本、相同长度和相同预算做对比。测试应留下样本数、统计周期、人工标准和失败案例，不能只挑好看的结果。

| 想知道什么 | 对应的记录 |
| --- | --- |
| 穿帮能不能找出来 | 人工标注的问题中，被系统正确指出的比例 |
| 会不会把正常转场也报错 | 正常片段中被误报的比例 |
| 重做之后有没有改善 | 定向修复后，经人工复核通过的比例 |
| 创作者有没有省事 | 检查时长、手动修改次数、重生成次数 |
| 花费是否值得 | 同期模型总消耗除以人工验收通过的成片数 |

目前只有工程测试与本地抽帧验证，还没有上述真实模型效果数据。
